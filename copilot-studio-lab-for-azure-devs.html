Shared terminology, naming, and assessment policy

Recorded Korean samples: This English guide retains executable code, exact input names, status values, and recorded Korean prompts unchanged so they match the original Korean recordings. English meanings are provided beside the samples; enter the original literals when reproducing the recorded labs.

A harness is a runtime. Distinguish Standard / GitHub Copilot(GHC) / Copilot chat harnesses. Topic is a Standard conversation flow; Agent flow is Standard automation; Workflow is GHC automation. Knowledge is a source registered during authoring; Attachment is a file uploaded by a user in a conversation.

Microsoft Foundry is the product name. In the connection UI, Azure AI Foundry is retained as the connector's name. Microsoft Agent Framework (MAF) is a code framework, not the same implementation or API as Studio GHC. Power Platform connectors provide API actions/triggers; Microsoft 365 Copilot connectors provide search and grounding connections.

Check permissions separately: authoring entitlement → environment role → Dataverse role → source ACL → connection authentication → Azure RBAC. DLP is a separate policy for connectors and their combinations; creating an Entra Agent ID does not itself grant data access.

Replace <LAB_PREFIX> in the instructions with your chosen prefix before entering it. There is no automatic substitution. Use the same prefix for agents, lists, flows, skills, and cleanup records. The administrator-provided LAB-DEV / LAB-TEST Sandbox names are examples, not instructions to create new environments.

Completion assessment: follow Goal → Actions → Verify → Cleanup. Saving or a connection indicator alone does not complete a lab. Common lab symptoms and the order to troubleshoot them.

I added knowledge, but only get “Information not found”
Check ① processing status is Ready; ② the user's SharePoint read permission and agent authentication remain valid; ③ source descriptions match the question; ④ product/vendor questions have not been mixed into HR instructions; ⑤ scanned/encrypted document restrictions; and ⑥ required Dataverse search settings for uploaded knowledge are enabled. Do not confuse file upload with SharePoint permission checks.
The tool exists, but the agent does not call it
First check the harness, orchestration, tool activation, authentication, and publishing state. Then check descriptions, input mappings, and allowed scope. Classic mode requires an explicit call from a topic. Workflows must meet L20's agent-call trigger, response, and publishing conditions; changing a description alone does not fix authentication/schema errors.
Connecting a Foundry Agent returns 400
endpoint does not support activity: use L08's GET to verify the actual Activity configuration. Apply a PATCH that preserves existing protocols/authentication, then verify with GET again. If the portal's Endpoints still shows only Responses/A2A after activation, that is an expected UI omission documented officially. Judge by GET results and actual successful calls, not portal display.

404 - Version not found is a typical error when connecting to an agent created in the previous/classic portal. First confirm the asset is from the new Foundry portal; also inspect the project endpoint, Agent ID, and active version. Do not assume every 404 has the same cause or immediately delete existing assets.
Foundry model connection shows Resource not found
Check that the endpoint URL ends with /chat/completions. /openai/v1/responses (Responses API) fails. Also, the GPT-5 family is not supported for prompt BYOM; switch to a supported model such as GPT-4.1. Enter the deployment and base model names exactly as shown in Foundry.

Check authentication separately: Native BYOM's API Key field and backend authentication are different boundaries. Sending a key to a direct Foundry endpoint conflicts with disabled local authentication, but the validated APIM endpoint removes the APIM key and calls the backend with MI. Separately verify keyless 401, backend RBAC, deployment/API version, and actual model responses. If switching to a separate REST/custom connector, label it an alternative integration.
I cannot add an event trigger
① Generative orchestration must be enabled. ② The environment must have solution-aware cloud flow sharing enabled (administrator). ③ Organizational DLP policy must allow the connector. ④ An administrator may have blocked event triggers in the environment.
I connected several MCP servers, but some tools do not run
A conversation has a limit on concurrently executable MCP servers. Excess servers are silently skipped for that turn. Remove unused servers and minimize MCP servers per agent. Each MCP server also counts toward the agent's total tool limit.
I published the agent, but it is not visible in Teams
Check ① publishing-capable entitlement rather than a trial; ② publishing and channel configuration are complete; ③ Teams Power Platform app policies allow it; ④ target users have agent-use permission; and ⑤ organizational catalog approval. Retest in a new conversation. ZIP upload follows separate policies and must not bypass a block.
The same question gets different answers in the test panel and Teams
The test panel and actual channel can differ in runtime, authentication, and published version, so results may differ. Earlier context in the same conversation also affects the next response; retest in a fresh conversation. Always perform final validation in a new conversation on the actual channel.
I suspect a permission blocker, but cannot identify it
Consider non-permission causes as well. For missing SharePoint documents, check read access/authentication/processing; for a missing trigger menu, generative mode/flow-sharing policy; for blocked publishing, licensing/DLP; for a missing model, region/administrator approval. For Foundry IQ, check Azure access; for Standard transcripts, Bot Transcript Viewer; for Teams installation, app policies and agent-sharing permissions.
Problems caused by selecting the wrong environment
Use the approved lab environment instead of the shared Default environment. Connections, flows, and Dataverse configuration belong to an environment, but external SharePoint/Azure/SaaS access depends on connection/source permissions. Environment region alone does not guarantee model/channel data residency. Check trial expiration, environment roles, and Dataverse roles separately.
Can users without a license use the agent?
Declarative agents (L19) require an M365 Copilot add-on license or Copilot Chat access through an eligible M365 license. For eligible Copilot Chat users, declarative agents using only instructions/public-web grounding have no additional consumption cost, but shared tenant data is subject to credit billing conditions. Custom engine agents can be accessible without a separate Copilot add-on license, but hosting/execution costs are separate. In particular, using GHC/Work IQ with public data does not make them free.

Note — Copilot Studio documentation states L19 prerequisites more strictly as “an M365 Copilot license for both makers and users.” Actual applicability may vary with tenant configuration; confirm with an administrator.
Costs are higher than expected
First break them down by the same period, subscription, and meter. ① A 10-minute recurrence means 144 daily execution attempts, not a fixed count of billed events; check downstream actions/retries. Also check ② GHC LLM-based authoring/testing/evaluation, ③ model/tool consumption, ④ pack/P3 application, and ⑤ ongoing costs for separate resources such as dedicated Search capacity. Stop lab-only automation first; for asset deletion, see verify ownership and dependencies first.
I enabled memory, but the agent does not remember
① User memory is disabled in group chats and Teams channels— check in 1:1 chat. ② Memory is automatically deleted after 28 days of inactivity. ③ The user may have deleted it in the memory portal. ④ Memory is isolated by user, so testing with another account shows no memory from the first.
