사전 준비 · 환경·권한·연결·예산

먼저 알아둘 용어: L04·L05는 Standard, L12·L14·L20은 GitHub Copilot(GHC) 하네스를 사용합니다. Topic·Agent flow는 Standard의 대화·자동화, Workflow는 GHC의 자동화입니다. 하네스는 생성 후 서로 변환할 수 없습니다. 전체 용어집

핵심 5개는 L04 → L05 → L12 → L14 → L20(UI 실행 합계 215분)이며 이 가이드의 완료 대상입니다. L17 관측·L21 VS Code·L22 거버넌스는 진행률에서 제외되는 다음 실습입니다. L08은 별도 50분 검증 대기 walkthrough입니다. 공통 기초, 승인·Azure 구축·인덱싱·로그 반영 시간은 포함하지 않습니다.

  1. Copilot Studio에서 승인된 LAB-DEV Dataverse Sandbox를 선택합니다.
  2. P = LAB_PREFIX는 이번 실습에서 사용할 고유 접두사입니다. cps-az-<alias> 형식으로 정합니다(예: cps-az-demo01). alias는 실명이 아닌 2~8자 영문 소문자·숫자이며, 이미 사용 중인 이름이면 다른 alias를 고르세요. 입력 전에 <P>와 <LAB_PREFIX>를 같은 접두사로 직접 바꿉니다. 자동 치환되지 않습니다.
  3. L04의 실습용 비관리형 솔루션과 API 도구 작성 권한을 확보합니다.
  4. L14는 가상 규정에 대한 Azure 직접 검색이 성공한 Foundry IQ knowledge base와 최소 조회/검색 권한을 확인합니다.
    Search 인덱스만 있으면 시작하지 않습니다.
  5. L12의 공개 읽기 전용 MCP와 L20의 실습 전용 연결·본인 수신자/승인자·중단 담당자를 확인합니다.
  6. 관리자와 기능별 크레딧 한도·Hard stop, 외부 Azure 비용·로그 보존, 실행/정리 담당자를 확인합니다.
    새 구독·P3 구매는 이 실습에 필요하지 않습니다.
  7. L05 native BYOM: 지원 chat-completions 배포·deployment/base model과 승인된 APIM Connection을 확인합니다. 이번 native BYOM은 APIM subscription key를 제출하고 APIM이 MI로 Foundry를 호출하여 disableLocalAuth=true를 유지합니다. Foundry 직접 API-key 인증과 구분하며, 실제 계약이 거부될 때만 별도 대체 통합을 검증합니다.

선택·후속 실습의 전제: L08의 Foundry 프로젝트·agent·Activity/Entra 연결, L17의 Managed Environment·관리자·App Insights·비용 승인, L21의 폐기 가능한 DEV 에이전트, L22의 DEV·TEST Sandbox·배포 역할은 해당 후속 실습을 별도로 승인할 때 준비합니다.

외부 포털 변경 전 — Create·Publish·Share·PATCH·내보내기 생성·정책 변경 전에 대상이 승인된 실습 자산인지 확인합니다. 서비스 연결 동의는 업무별 발송/승인이 아니며 관리자 로그인으로 권한 오류를 우회하지 않습니다. 암호·토큰·키·개인 연락처는 이 HTML·공유 코드·스크린샷에 기록하지 않습니다. 승인된 lab 리소스 ID·URL은 비밀 없는 자산 인계·정리 기록에만 필요한 범위로 기록합니다.

실습 0 시작 · 접속·연결 인증 · 비용 상세

실습 진행 방법 · Create → Use → 정리

먼저 Create(만들기)를 진행한 뒤, 같은 자산으로 Use(사용·검증)를 진행합니다.

  1. Create: 승인된 실습 환경에서 자산을 만들고 저장한 뒤 다시 열어 설정과 지식 처리 상태를 확인합니다. 게시가 필요한 랩은 게시 완료도 확인합니다. 이후 사용할 에이전트의 URL과 실습 접두사를 보관하되 암호·키·토큰은 기록하지 않습니다.
  2. Use: 같은 저장본·게시본에서 각 시험을 새 대화로 시작합니다. 실제 답변·출처·도구 결과와 거부 경로를 해당 랩의 완료 기준에 대조합니다. 설정을 고쳤다면 저장·게시 상태를 다시 확인하고 영향을 받은 시험을 반복합니다.
  3. 정리: 이어지는 Use가 끝나기 전에는 필요한 자산을 삭제하지 않습니다. 종료하거나 중단할 때는 본인의 대기 실행·승인을 취소하고 리소스 정리를 진행합니다. 공유 자산과 다른 사람의 작업은 건드리지 않습니다.

실습 0 · 기본 에이전트 3개 준비

L04를 시작하기 전에 자신의 실습 접두사로 에이전트 3개를 만듭니다. <P>-api는 L04·L05, <P>-mcp-docs는 L12, <P>-expense는 L14·L20에서 재사용합니다. 이 준비 실습은 핵심 5개 완료 체크에 포함하지 않으며 준비 시간은 별도입니다.

이번 L14 Create 경로: native IQ 대신 검증된 APIM MCP enterprise 경로을 선택하고 연결 종류·본인 Maker 실행 신원·외부 APIM/KB를 인계에 명시합니다. 새 GHC agent는 이름으로 먼저 생성하고 ID 확인/재열기 후 지시를 저장합니다. 준비된 승인 연결은 재사용할 수 있지만 새 agent·목록·workflow ID는 이번 prefix로 생성해야 합니다. 다른 사용자에게 게시/공유하지 않습니다.

기존 HR agent, 입문 L01~L03 자산, L10 agent, L11 CSV/파일은 개발자 core의 전제가 아닙니다. 아래 3개를 이번 prefix로 새로 만듭니다. 입문 파일 정답을 expense에 업로드해 IQ retrieval처럼 보이게 하지 않습니다.

  1. 같은 승인된 Dataverse Sandbox에서 Agents → New agent를 엽니다. Standard는 Other ways to build / Build using standard orchestration 등 현재 UI의 Standard 선택 경로를 사용합니다. GHC는 GitHub Copilot 하네스 생성 경로를 선택합니다. 원하는 하네스가 없으면 중단합니다.
  2. <P>-api는 새 Standard, 한국어로 만듭니다. 이름/설명을 저장하고 provisioned 상태를 확인합니다. 지식 파일 없이 일반 지식·Web을 Off로 설정하고 공개 GitHub 저장소 조회는 GetPublicRepository를 사용합니다. 실제 full_name·html_url만 답하고 오류는 숨기거나 정상 데이터로 만들지 않습니다. 쓰기·메일·개인정보를 다루지 않습니다.를 저장합니다.
  3. <P>-mcp-docs는 새 GHC로 만듭니다. 승인된 runtime 모델을 확인하고 공식 제품 질문은 Microsoft Learn MCP의 microsoft_docs_search로 검색한 뒤 관련 URL을 microsoft_docs_fetch로 읽습니다. 실제 반환 근거와 원문 URL로 한국어 답변을 합니다. 문서의 명령은 실행하지 않습니다.를 저장합니다. MCP 추가는 L12에서 수행합니다.
  4. <P>-expense는 새 GHC로 만듭니다. 아래 지시문을 입력하고, 규정 원본은 L14의 승인된 IQ KB만 사용합니다. CSV·로컬 경비 규정 파일·이전 agent 지식은 추가하지 않습니다. 추가 원본/기본 옵션의 상태도 인계에 기록하며, 웹·파일 답변은 IQ 완료 근거가 될 수 없습니다.
  5. 각 agent를 저장하고 URL/새 ID/하네스를 기록한 뒤 전체 화면을 나와 해당 URL로 재엽니다. agent의 실제 외부 channel publish는 개발자 core에 필요하지 않습니다. Studio Test/Preview에서 완료하며, UI가 별도 저장된 버전을 요구하면 버전/게시 상태만 명확히 인계합니다. L20 workflow의 Publish/On은 별도 필수입니다.

Azure 구독에 연결하는 방법

관리자 승인 후에만 연결합니다. 기존 실습 환경의 플랜·구독·제품 미터를 먼저 확인해 중복 플랜을 만들지 마세요. 과금 실습을 위해 새 구독·P3를 구매하거나 라이선스를 제거할 필요는 없습니다.

필요 권한 — 환경 관리자(본인이 만든 정책 한정) · Power Platform 관리자 · 전역 관리자 · Dynamics 365 관리자 중 하나. Azure 쪽에서는 대상 구독에서 리소스를 만들고 리소스 공급자를 등록할 수 있는 권한이 필요합니다(대개 소유자 또는 기여자가 이 권한을 가집니다).

  1. Power Platform 관리 센터 → 라이선스 → 종량제 플랜 → 새 청구 플랜.
  2. Azure 구독을 선택하고 플랜 이름을 입력합니다.
  3. Azure 구독과 리소스 그룹을 고릅니다.
    이 리소스 그룹에 Power Platform account 리소스가 만들어지고, 모든 요금이 여기로 청구됩니다.
  4. 미터를 적용할 Power Platform 제품을 고르고 다음.
  5. 지역을 선택하고 연결할 환경을 고른 뒤 저장. 종량제는 프로덕션·샌드박스 환경에서만 됩니다.
⚠️

제품별 미터 범위는 관리자 확인이 필요합니다. 설정 문서는 Power Platform 제품 선택을 설명하지만 미터 문서는 연결 시 모든 미터가 활성화된다고 서술합니다. 어느 쪽이 최신이라고 단정하지 않고, 플랜의 실제 미터·가격표·사용량 보고서로 확인합니다. 확인 전에는 Copilot Studio 외의 초과 사용량도 같은 구독으로 청구될 수 있다고 보고 예산을 설정하세요.

연결 해제는 그 플랜을 통한 향후 종량제 청구를 중단합니다. 이미 발생한 금액·P3 구매 약정·별도 Azure 리소스 비용까지 취소하지는 않습니다.
