Shared terminology, naming, and assessment policy

A harness is the runtime. The three harnesses are Standard / GitHub Copilot(GHC) / Copilot chat. Topic is a Standard conversation flow; Agent flow is Standard automation; Workflow is GHC automation. Knowledge is a source registered during authoring; Attachment is a file a user uploads in a conversation.

Microsoft Foundry is the product name. In the connection UI, Azure AI Foundry remains the actual connector name. Microsoft Agent Framework(MAF) is a code framework, not the same implementation or API as Studio GHC. Power Platform connectors provide API actions/triggers; Microsoft 365 Copilot connectors provide search/grounding connections.

Check permissions separately: authoring entitlement → environment role → Dataverse role → source ACL → connection authentication → Azure RBAC. DLP is a separate connector/combination policy; creating an Entra Agent ID does not grant data access.

LAB_PREFIX is cps-basic-<alias> for the beginner guide and cps-az-<alias> for the developer guide. Use an alias, not a real name: 2–8 lowercase English letters/digits (for example, demo01 ). Replace <LAB_PREFIX> in this guide with your chosen prefix before entering it. There is no automatic substitution. Use the same prefix for agents, lists, flows, skills, and cleanup records. The environment names LAB-DEV / LAB-TEST are examples of administrator-provided Sandboxes, not instructions to create new environments.

Completion assessment: Follow Goal → Actions → Verify → Cleanup. Saving or a connected indicator alone is not completion. An expense intake ID returned, but approval/rejection/expiration is wrong
L20 — follow agent → intake → dedicated SharePoint item → separate approval, comparing actual input/output, requestId, and the same row ID. Required: rejection without a new row, 300000 automatic approval, and separate 300001 approval/rejection. Unanswered means awaiting approval. Do not invent final approval without an actual outcome. Actual Approval timeout is optional, and Canceled/Cancelled != Expired. A deterministic error branch, short Delay, or manual cancellation is not actual timeout evidence. Check duplicate rows before retrying; clean up only lab-pending items after Use. These criteria do not apply to L04 Standard Agent flow or L07 event triggers.
Foundry Agent connection returns 400
endpoint does not support activity — for this error, use L08 GET to inspect actual Activity settings. Apply a PATCH that preserves existing protocols/authentication and reverify with GET. Seeing only Responses/A2A in portal Endpoints after enablement is an expected UI omission documented officially. Judge by GET results and actual call success, not portal display.

404 - Version not found occurs when connecting to agents created in the old portal. First verify the asset belongs to the new Foundry portal; also inspect project endpoint, agent ID, and active version. Do not assume every 404 has the same cause or immediately delete existing assets.
Foundry model connection shows Resource not found
Verify the endpoint URL ends in /chat/completions. /openai/v1/responses (Responses API) fails here. Also, the GPT-5 family is unsupported in prompt BYOM; use GPT-4.1 or another supported model. Enter deployment/base-model names exactly as shown in Foundry.
Cannot add an event trigger
① Generative orchestration must be enabled; ② the environment's Solution-aware cloud flow sharing must be enabled (administrator); ③ organizational DLP policies must allow the connector; ④ the administrator may have blocked event triggers in the environment.
Multiple MCP servers are attached, but some tools do not work
A conversation has a limit on concurrently used MCP servers. Excess servers are silently skipped for that turn. Remove unused servers and minimize MCP servers per agent. Each also counts toward the agent's total tool limit.
Published, but the agent is not visible in Teams
Check ① publishing-capable entitlement, not trial-only ② publishing/channel configuration completed ③ Teams Power Platform apps allowed ④ target-user agent-use permission ⑤ organization-catalog approval. Retest in a new conversation. ZIP upload follows separate policies and does not bypass blocks.
The same question gives different answers in the test pane and Teams
The test pane and actual channel may use different runtimes, authentication, and published versions. Prior context also affects subsequent answers; retest in a new conversation. Always perform final verification in a new actual-channel conversation.
It seems permission-related, but I cannot identify the symptom
Consider nonpermission causes too. Missing SharePoint documents: read permissions/authentication/processing. Missing trigger menu: generative mode/flow-sharing policy. Blocked publishing: license/DLP. Missing models: region/administrator allowance. For Foundry IQ, separately verify saved KB/API/Connection, runtime identity, and actual retrieval traces; do not infer the cause solely from Azure permissions. For L20, separately check SharePoint writes, Approvals connection, and self-response. Standard transcripts require Bot Transcript Viewer; Teams installation requires app policies/agent sharing.
Problems caused by choosing the wrong environment
Use an approved lab environment, not shared Default. Connections/flows/Dataverse belong to an environment; external SharePoint/Azure/SaaS access depends on connections/source permissions. Environment region alone does not guarantee model/channel data residency. Check Trial expiration and environment/Dataverse roles separately.
Can users without a license use the agent?
Declarative agents (L19) require an M365 Copilot add-on license or Copilot Chat access under an eligible M365 license. For eligible Copilot Chat users, declarative agents grounded only in instructions/public web have no additional consumption charge; shared tenant data has credit-billing conditions. Custom engine agent can be accessed without a separate Copilot add-on license, but hosting/execution costs are separate. In particular, using GHC or Work IQ with public data does not make it free.

Note: Copilot Studio documentation states L19 prerequisites more strictly as “M365 Copilot licenses for both makers and users.” Actual applicability can vary by tenant configuration; check with the administrator.
Costs are higher than expected
First compare the same period, subscription, and meters. ① A 10-minute interval means 144 daily execution attempts, not a fixed billable count; inspect downstream work/retries. Check ② GHC LLM-based authoring/testing/evaluation ③ model/tool consumption ④ pack/P3 coverage ⑤ ongoing costs of separate resources such as dedicated Search capacity. Stop lab-only automation first; delete assets only after checking owners/dependencies.
Memory is enabled, but the agent does not remember
① User memory is disabled in group chats and Teams channels — test in 1:1 chat. ② Memory is automatically deleted after 28 days without interaction. ③ The user may have deleted it in the memory portal. ④ Memory is per-user, so another test account has different/empty memory.
